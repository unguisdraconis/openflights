# Repository Working Instructions

## Purpose

This repository is part of Jeremiah King's professional portfolio.
The work should demonstrate clear thinking, factual documentation,
maintainable code, accessibility, and responsible use of data.

## Factual Accuracy

- Do not invent metrics, outcomes, credentials, employment, or proficiency.
- Base project descriptions on the repository contents and approved
  content files.
- Distinguish academic prototypes from production systems.
- Distinguish individual work from collaborative or course-provided work.
- Do not add French or Portuguese to any profile or document.
- Do not publish a street address, transcript, student identifier,
  certificate number, or application-specific résumé.

## Documentation

Every featured repository README should include:

- project purpose and audience
- live demo when available
- screenshot with meaningful alt text
- my role
- methods and technologies
- data source, license, provenance, and limitations
- accessibility decisions
- local setup and build instructions
- limitations and next steps
- AI-assistance disclosure when materially relevant

## Engineering

- Inspect the existing code before editing.
- Preserve functioning behavior unless the task explicitly requests change.
- Avoid unnecessary dependencies.
- Use semantic HTML and accessible controls.
- Support keyboard navigation and visible focus.
- Respect prefers-reduced-motion.
- Do not communicate essential information by color alone.
- Keep components focused and content separated from presentation.

## Validation

Before declaring work complete:

1. Install dependencies using the existing lockfile.
2. Run available lint, test, and build commands.
3. Report every command and result.
4. Check for broken links and missing assets.
5. Review the final git diff.
6. Leave the working tree clean.

## Git Safety

- Work on a task-specific branch.
- Do not force-push.
- Do not rewrite repository history without explicit approval.
- Do not merge directly into the default branch.
- Do not deploy without explicit approval.
- Make focused commits with descriptive messages.
